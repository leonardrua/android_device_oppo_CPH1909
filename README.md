# OPPO A5s (CPH1909) device tree starter

This standalone repository contains a starter device tree for an Android 8.1 /
API 27 based ROM. Clone it into `device/oppo/CPH1909` in an Android source tree.

## What it is based on

- `rom-dump/system/build_default.prop` identifies the product as OPPO A5s,
  model/device `CPH1909`, hardware project `18511`, and Android 8.1.
- `rom-dump/vendor/build.prop` reports MediaTek platform `mt6765`; the stock
  vendor fstab is copied to `rootdir/etc/fstab.mt6765`.
- Partition sizes and the eMMC flash block size come from the supplied MT6765
  scatter file and are set in `BoardConfig.mk`.
- The kernel tree contains `arch/arm64/configs/oppo6765_18511_defconfig` and
  `arch/arm64/boot/dts/mediatek/oppo6765_18511.dts`. The defconfig selects the
  MT6765 base DTB plus this board overlay and emits `Image.gz-dtb`.
- Boot base, offsets, and page size in `BoardConfig.mk` come from the unpacked
  metadata under `rom-dump/boot/`.

## Use

Clone this repository into an Android 8.1 source checkout as
`device/oppo/CPH1909`. Place the kernel repository at
`kernel/oppo/CPH1909`, then select `aosp_CPH1909-userdebug` after sourcing
`build/envsetup.sh`.

## Extract vendor files

After placing this device tree in an Android source checkout and sourcing
`build/envsetup.sh`, run:

```sh
device/oppo/CPH1909/extract-files.sh /path/to/rom-dump
```

The source directory must contain `vendor/` (or pass the `vendor/` directory
itself). The script copies the paths in `proprietary-files.txt` into
`vendor/oppo/CPH1909/proprietary/` and generates
`vendor/oppo/CPH1909/CPH1909-vendor.mk`, which `device.mk` includes. The
manifest covers the dumped vendor partition except `build.prop` and
`default.prop` (generated by Android) and `etc/fstab.mt6765` (kept in this
device tree).

This is still a starter ROM tree, not a complete flashable ROM. The supplied
scatter defines a 256 MiB `odm` partition but gives it no image
(`file_name: NONE`, `is_download: false`), and the device's raw ODM dump was
confirmed to contain only zero bytes. It also defines `userdata` as 3 GiB
(`0xC0000000`). There are no stock ODM files to add to the proprietary
manifest; the manifest therefore covers the vendor partition only.

## Recovery reference

The recovery mount table at `recovery/root/etc/twrp.fstab` adapts the CPH1909
TWRP reference tree and the stock fstab in the ROM dump. It leaves out ODM
because that partition is empty on the supplied dump. TWRP-specific options in
`BoardConfig.mk` are groundwork for a compatible TWRP/Omni build; this repo
currently defines only the `aosp_CPH1909` product, so it is not yet a standalone
TWRP build target. Encryption support also depends on the recovery tree and
matching vendor libraries.

The recovery ramdisk uses `init.recovery.mt6765.rc` for Trustonic, Keymaster,
Gatekeeper, and recovery keystore services, and `init.recovery.usb.rc` for the
MT6765 ConfigFS gadget with FunctionFS ADB/MTP. `recovery/root/trustonic.rc`
supplies the Trustonic daemon setup imported by the MT6765 fragment. The TWRP
default USB init is disabled to avoid competing gadget setup. USB mass-storage
LUNs are mapped to the ConfigFS gadget path in `BoardConfig.mk`.

The supplied stock `recovery.img` is a legacy Android boot image with 2048-byte
pages. Its header reports kernel address `0x40080000`, ramdisk address
`0x55000000`, and tags address `0x54000000`, matching the base and offsets in
`BoardConfig.mk`. The compressed kernel carries the same valid base FDT as the
boot dump. Its ramdisk `etc/recovery.fstab` confirms the metadata-based data
encryption and the `odmdtbo` by-name node; TWRP exposes `odmdtbo` for backup.
